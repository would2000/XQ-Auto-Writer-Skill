# CODEX 操作 XQ 軟體憲法

本憲法是 XQ Auto Writer 專案所有 XQ 桌面操作、XScript 建檔、策略執行、測試及清理的最高優先持久規則。`AGENTS.md`、Skill、工具腳本、操作指南或單次工作流程若與本憲法衝突，以本憲法為準。只有使用者後續明確要求修改本憲法，才能改變這些規則；不得由代理自行放寬。

## 適用範圍與定義

- 「私人區域」：XQ 中所有不在已驗證 CODEX 專用資料夾內的腳本、策略、函數、頁面、分類、帳號設定及其他既有內容；亦包含無法證明由 CODEX 在本次工作建立的項目。
- 「CODEX 專區」：在各功能內另外建立、名稱明確為 `CODEX` 的專用資料夾或分類，供 CODEX 建立測試及使用者要求的項目。進入或操作前必須讀回並證明目前位於該專區。
- 「本次 manifest」：記錄本次工作實際建立項目的私有清單。可刪除範圍不得超出 manifest，且刪除前後都必須取得名稱、類型、位置及不存在證據。
- 「使用者指定成果」：使用者要求保留的腳本及其必要函數。這些成果不是任務結束時應刪除的測試產物。

CODEX 專區並不解除帳號禁令、慢速操作、證據及清理規則。若 XQ 版本或功能無法建立、選取或讀回 CODEX 專區，立即停止並向使用者說明；不得退回私人區域建立測試項目。

## 第一條：原生私人內容不可變

1. 未經使用者對精確目標另行指定，CODEX 絕對不得修改、編輯、覆寫、移動、重新命名或刪除原生 XQ 私人腳本及私人區域內容。
2. 如工作需要私人程式碼，只允許複製與唯讀讀取。修改只能發生在經驗證的 CODEX 專區副本，不得回寫原件。
3. 無法證明項目位於 CODEX 專區或屬於本次 manifest 時，一律視為私人內容。

## 第二條：所有 CODEX 項目必須隔離

1. CODEX 進行測試或撰寫指標、選股、警示、函數、自動交易五類 XScript 時，必須在每個對應類型的自訂範圍內建立或使用 `CODEX` 專用資料夾。
2. 在選股中心建立或執行策略、在策略雷達建立或執行策略、將自動交易腳本加入功能或進行回測時，也必須使用該功能中另外建立且已讀回的 `CODEX` 專用資料夾或分類。
3. CODEX 專區是代理可操作範圍；其他資料夾僅允許複製與唯讀讀取。即使位於 CODEX 專區，刪除仍須符合本次 manifest、精確讀回及使用者成果保留規則。
4. 專區資料夾可以保留，方便後續分類與使用者檢查。
5. 五類 XScript 新建文件與補建 CODEX 資料夾的標準路徑固定為：開啟「新增腳本」→先選取並讀回腳本類型→使用「儲存位置」的資料夾控制開啟該類型限定的「選擇資料夾」→在唯一 `自訂` 根節點下檢查唯一直接子節點 `CODEX`→缺少時才新增精確 `CODEX`→選取後從新增腳本對話框讀回精確 `自訂/CODEX/`→才允許建立腳本。不得為新建文件改用自繪分類頁籤、其他私人資料夾、重名 CODEX、座標或推測命令。
6. 整理既有腳本而需要切換五類自繪分類時，使用者必須先手動切換到指定類別；CODEX 只能以 `xq_category_selector.py` 唯讀讀回唯一可見分類及其 `自訂/CODEX/`，不送切換輸入。未讀回成功時停止，不得建立臨時空腳本、雙擊文件頁籤、使用座標、密集點擊或推測命令切換。

## 第三條：帳號與實單操作全面禁止

1. CODEX 不得操作 XQ 軟體帳號的登入或登出。
2. CODEX 不得串接、登入、登出或選取任何實際證券帳號。
3. CODEX 不得操作實際證券帳號下單功能，不得讓策略雷達或自動交易設定串接實單帳號，也不得送出實單。
4. 測試若需要帳號，只允許使用 XQ 內建模擬帳號。無法明確證明是內建模擬帳號時，停止操作並請使用者處理。
5. 登入狀態不足時，由使用者自行登入；CODEX 只能等待並於使用者確認後重新執行唯讀健康檢查。

## 第四條：慢速操作與故障事件

1. 學習或操作 XQ 的任何視窗時，絕對不得使用固定座標、相對座標、依視窗矩形計算的座標或幾何位置猜測目標。不同使用者環境及每次開啟視窗的配置與大小都不保證相同。
2. 每個 UI 目標都必須以可讀回的 Win32 control ID、UI Automation automation ID、控制項類型、名稱、父子階層、選取狀態或正式選單命令唯一識別。只能對已唯一識別的控制項執行控制項層級的 `Invoke`、`Select`、`Click` 或鍵盤命令；不得傳入 `coords`。沒有穩定選擇器時立即停止並重新校正，不得以座標補救。
3. 所有 XQ 輸入必須節流，使用參數化等待、自適應唯讀輪詢及動作間隔，禁止密集點擊、連續快捷鍵或快速掃描分類。
4. Windows 無回應、`WaitGuiThreadIdle`、視窗長時間 disabled、對話框晚到或 timeout 時，立即停止後續輸入，不得用替代快捷鍵或其他點擊繞過等待。
5. 事件至少保存 UTC 時間、工作／案例、文件、階段、XQ PID、視窗 visible／enabled／hung 健康、checkpoint、可見報告及唯讀 recovery-status。
6. 事件發生後先分析可觀察證據，再向使用者回報。不得把 timeout 推測成 XQ 錯誤碼、斷網或當機；不得對真實 XQ 注入當機或斷網來測試。

## 第五條：任務結束清理與視窗復原

1. 使用者指定成果及其必要函數必須保留。
2. 本次工作建立的測試腳本、測試函數、選股策略、雷達策略、自動交易測試項目、回測報告、checkpoint 及暫存輸出必須清理；CODEX 專用資料夾可以保留。
3. 每個刪除項目必須屬於本次 manifest，刪除前讀回完全相同的名稱、類型及 CODEX 專區位置，刪除後再驗證不存在。證據不足時拒絕刪除並回報。
4. 任務結束時檢查 XQ 是否仍有本次開啟且應關閉的對話框、報告、進度或子視窗；只關閉本次工作或明確不再使用的視窗，不影響使用者原有視窗。
5. 依工作類型保留方便使用者後續查看的相關 XQ 視窗，不得只為任務收尾而關閉：
   - 撰寫或編譯腳本：保留本次成果腳本及其 XScript 編輯視窗。
   - 操作 XScript 編輯器，例如建立資料夾或整理腳本：保留 XScript 編輯器及相關分類或位置。
   - 將指標展示在技術線圖：保留已顯示該指標的技術線圖畫面。
6. 無論前款保留哪一種 XQ 視窗，任務完成的最後前景一律切回 ChatGPT／Codex；相關 XQ 視窗應維持開啟，不要求仍位於前景。
7. 必須驗證 ChatGPT／Codex 可見且位於前景，並驗證前款要求保留的相關 XQ 視窗仍存在；若環境故障導致無法完成，必須明確回報，不得默認完成。

## 第六條：Print 除錯輸出必須隔離

1. 使用 `Print` 語法除錯時，必須明確指定新的隔離輸出資料夾，避免與 XQ 原生檔案或使用者檔案混雜。
2. 使用者指定的路徑與檔名語法如下；實際使用仍須由當次 XQ 編譯結果驗證：

   ```xs
   print(file("C:\print\"),date,symbol,close);
   print(file("c:\Print\[Symbol].log"),date,symbol,close);
   ```

3. 使用者同時指定「使用者桌面的新資料夾」及上述 `C:\Print\` 範例。兩者在實際環境可能不是同一路徑，因此每次第一次啟用 Print 檔案輸出前，必須向使用者確認最終目標；不得自行猜測、沿用 XQ 預設目錄或覆寫既有檔案。
4. 確認目標後，只能建立新的 CODEX 專用輸出資料夾與新檔案；不得把輸出寫入原生 Print 資料夾。輸出內容不得包含帳號、憑證、私人部位或其他敏感資料。
5. 官方參考：[功能介紹：如何使用 Print 指令進行腳本除錯？](https://www.xq.com.tw/learning/%E5%8A%9F%E8%83%BD%E4%BB%8B%E7%B4%B9%EF%BC%9A%E5%A6%82%E4%BD%95%E4%BD%BF%E7%94%A8print%E6%8C%87%E4%BB%A4%E9%80%B2%E8%A1%8C%E8%85%B3%E6%9C%AC%E9%99%A4%E9%8C%AF%EF%BC%9F/)。該頁的企業版預設路徑不應套用為個人版假設；使用者提供的個人版預設安裝位置為 `C:\SysJust\XQLite`。

## 操作前後檢查

任何會接觸 XQ 的工作都必須：

1. 操作前讀取本憲法。
2. 確認目標位於已讀回的 CODEX 專區；私人來源只建立副本。
3. 確認不會登入、登出、串接或操作實單帳號。
4. 只使用可驗證控制項與正式命令，完全不使用座標；採用慢速等待並先執行工作所需的唯讀 recovery／健康檢查。
5. 任務後保留使用者成果、清除 manifest 測試產物、檢查視窗，依第五條保留相關 XQ 成果視窗，最後將 ChatGPT／Codex 切回前景並驗證。
