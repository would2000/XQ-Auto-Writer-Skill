# CODEX 操作 XQ 軟體憲法

本憲法是 XQ Auto Writer 專案所有 XQ 桌面操作、XScript 建檔、策略執行、測試及清理的最高優先持久規則。`AGENTS.md`、Skill、工具腳本、操作指南或單次工作流程若與本憲法衝突，以本憲法為準。只有使用者後續明確要求修改本憲法，才能改變這些規則；不得由代理自行放寬。

## 適用範圍與定義

- 「私人區域」：XQ 中所有不在已驗證 CODEX 專用資料夾內的腳本、策略、函數、頁面、分類、帳號設定及其他既有內容；亦包含無法證明由 CODEX 在本次工作建立的項目。
- 「CODEX 專區」：在各功能內另外建立、名稱明確為 `CODEX` 的專用資料夾或分類，供 CODEX 建立測試及使用者要求的項目。進入或操作前必須讀回並證明目前位於該專區。
- 「本次 manifest」：記錄本次工作實際建立項目的私有清單。可刪除範圍不得超出 manifest，且刪除前後都必須取得名稱、類型、位置及不存在證據。
- 「使用者指定成果」：使用者要求保留的腳本及其必要函數。這些成果不是任務結束時應刪除的測試產物。

CODEX 專區並不解除帳號禁令、慢速操作、證據及清理規則。若 XQ 版本或功能無法建立、選取或讀回 CODEX 專區，立即停止並向使用者說明；不得退回私人區域建立測試項目。

## 第一條：原生私人內容不可變

1. 未經使用者對精確目標另行指定，CODEX 絕對不得修改、編輯、覆寫、移動、重新命名或刪除原生 XQ 私人腳本及私人區域內容。
2. 如工作需要私人程式碼，只允許複製與唯讀讀取。修改只能發生在經驗證的 CODEX 專區副本，不得回寫原件。
3. 無法證明項目位於 CODEX 專區或屬於本次 manifest 時，一律視為私人內容。

## 第二條：所有 CODEX 項目必須隔離

1. CODEX 進行測試或撰寫指標、選股、警示、函數、自動交易五類 XScript 時，必須在每個對應類型的自訂範圍內建立或使用 `CODEX` 專用資料夾。
2. 在選股中心建立或執行策略、在策略雷達建立或執行策略、將自動交易腳本加入功能或進行回測時，也必須使用該功能中另外建立且已讀回的 `CODEX` 專用資料夾或分類。
3. CODEX 專區是代理可操作範圍；其他資料夾僅允許複製與唯讀讀取。即使位於 CODEX 專區，刪除仍須符合本次 manifest、精確讀回及使用者成果保留規則。
4. 專區資料夾可以保留，方便後續分類與使用者檢查。
5. 五類 XScript 新建文件與補建 CODEX 資料夾的標準路徑固定為：開啟「新增腳本」→先選取並讀回腳本類型→使用「儲存位置」的資料夾控制開啟該類型限定的「選擇資料夾」→在唯一 `自訂` 根節點下檢查唯一直接子節點 `CODEX`→缺少時才新增精確 `CODEX`→選取後從新增腳本對話框讀回精確 `自訂/CODEX/`→才允許建立腳本。不得為新建文件改用自繪分類頁籤，不得改用其他私人資料夾、重名 CODEX 或推測命令；若標準路徑內的自繪控制項確實沒有可用語意介面，只能依第四條的受控座標例外操作，而且最終仍須讀回精確 `自訂/CODEX/`。
6. 整理既有腳本而需要切換五類自繪分類時，先使用可讀回控制項或正式命令；XQ 3.19.03 已證明該頁籤沒有可用的 UIA／MSAA 選取動作、具名控制項、正式命令或文件化快捷鍵，因此校正後的標準替代路徑為 `xq_category_selector.py`：每次從目前公式 host 的記憶體截圖重新偵測五個穩定頁籤區段，以原生內容 pane 讀回交叉驗證唯一作用中頁籤，只對目標區段送出一次節流點擊，隨即讀回目標分類及唯一 `自訂/CODEX/`。不得保存或沿用螢幕座標、比例或成功截圖；偵測不唯一、畫面／前景改變、分類或 CODEX 讀回不符時立即停止。開啟既有文件時，只能用 `xq_open_existing_script.py` 完整名稱匹配唯一的 CODEX 直接子文件，以當次 TreeView 局部截圖定位可見範圍內的一次雙擊，再讀回相同名稱、類型與精確 `自訂/CODEX/`；不得列舉或開啟私人資料夾、建立臨時空腳本、密集點擊或推測命令繼續。
7. 歷史回測的「商品」選擇器是本次回測的暫時範圍，不是自選股、群組、帳號、策略或 XScript 資料夾。當使用者指定商品範圍，或已明示採用的預設範圍時，CODEX 可以在該回測商品選擇器內清空既有選取，再加入該完整範圍；清空後必須讀回為空，加入後必須讀回與指定集合完全一致。不得以此操作修改任何自選股、群組、帳號、策略或私人項目；未明示的「預設範圍」不得自行推測。

## 第三條：帳號與實單操作全面禁止

1. CODEX 不得操作 XQ 軟體帳號的登入或登出。
2. CODEX 不得串接、登入、登出或選取任何實際證券帳號。
3. CODEX 不得操作實際證券帳號下單功能，不得讓策略雷達或自動交易設定串接實單帳號，也不得送出實單。
4. 測試若需要帳號，只允許使用 XQ 內建模擬帳號。無法明確證明是內建模擬帳號時，停止操作並請使用者處理。
5. 登入狀態不足時，由使用者自行登入；CODEX 只能等待並於使用者確認後重新執行唯讀健康檢查。

## 第四條：慢速操作與故障事件

1. 學習或操作 XQ 視窗時，必須優先使用可讀回的 Win32 control ID、UI Automation automation ID、控制項類型、名稱、父子階層、選取狀態、MSAA 動作或正式選單／鍵盤命令；能使用語意控制時不得改用座標。
2. 只有當任務所需的 XQ 自繪控制項已實際探測，且確認沒有可用的 UIA、MSAA、control ID、具名子項、選取動作或正式命令時，才允許把座標當作最後手段。座標操作必須同時符合：
   - 目標屬於使用者本次明確要求的按鈕、清單或設定，且所在 XQ 視窗、對話框、分頁、腳本與 Plot／項目已用可讀證據識別。
   - 使用目前畫面重新擷取的目標視窗或彈窗矩形計算相對位置；不得沿用跨工作階段的固定螢幕座標，不得在視窗移動、縮放、DPI、內容或前景狀態改變後繼續使用舊座標。
   - 每次只執行一個節流點擊；點擊前確認 XQ 位於前景且目標視窗可見、啟用、未無回應，點擊後以控制項狀態、文字、Plot 名稱、畫面截圖或實際結果交叉驗證。無法驗證、選單關閉、版面改變或命中不明時立即停止。
   - 優先在已唯一識別的目標控制項／彈窗內使用局部相對座標，不得用整個桌面或主視窗的大範圍幾何猜測。
3. 座標例外絕對不得用於 XQ 登入／登出、真實證券帳號、券商串接、帳號選擇或設定、實單下單／刪單／改單、實際部位／庫存同步，亦不得藉此規避私人內容不可變、CODEX 專區、manifest、刪除證據或其他安全規則。這些禁止項目即使語意控制不可讀也必須停止。
4. 所有 XQ 輸入必須節流，使用參數化等待、自適應唯讀輪詢及動作間隔，禁止密集點擊、連續快捷鍵或快速掃描分類。操作節奏採 1 至 10 級，預設為 5；1 最慢、10 最快，7 在未碰到安全下限時約比第 5 級快 50%。節奏只得調整兩次輸入間的等待與鍵盤送字間隔，絕不縮短逾時判定、晚到對話框門檻、唯讀健康檢查或各工作流的安全下限；未經使用者指定時必須使用第 5 級。
5. 除回測、選股執行或其他已知需要伺服器回應的流程外，本機 XQ 視窗狀態不得長時間盲等。語意控制或正式狀態讀取未在短時間內完成時，先停止追加輸入，直接擷取已精確識別的目標 XQ 視窗或對話框（不得截取整個桌面），從真實可見畫面判斷目前階段、訊息與控制狀態，再決定是否繼續。畫面證據不能取代編譯成功、報告、checkpoint 關聯或其他既有安全閘門，也不能授權重複輸入。
6. Windows 無回應、`WaitGuiThreadIdle`、視窗長時間 disabled、對話框晚到或 timeout 時，立即停止後續輸入，不得用替代快捷鍵或其他點擊繞過等待。
7. 事件至少保存 UTC 時間、工作／案例、文件、階段、XQ PID、視窗 visible／enabled／hung 健康、checkpoint、可見報告及唯讀 recovery-status。使用座標例外時，另記錄使用原因、目標視窗／控制項證據、相對定位基準、前後驗證及是否命中預期；不得保存帳號、私人策略內容或整份原始控制樹。
8. 事件發生後先分析可觀察證據，再向使用者回報。不得把 timeout 推測成 XQ 錯誤碼、斷網或當機；不得對真實 XQ 注入當機或斷網來測試。

## 第五條：任務結束清理與視窗復原

1. 使用者指定成果及其必要函數必須保留。
2. 本次工作建立的測試腳本、測試函數、選股策略、雷達策略、自動交易測試項目、回測報告、checkpoint 及暫存輸出必須清理；CODEX 專用資料夾可以保留。
3. 每個刪除項目必須屬於本次 manifest，刪除前讀回完全相同的名稱、類型及 CODEX 專區位置，刪除後再驗證不存在。證據不足時拒絕刪除並回報。
4. 任務結束時檢查 XQ 是否仍有本次開啟且應關閉的對話框、報告、進度或子視窗；只關閉本次工作或明確不再使用的視窗，不影響使用者原有視窗。
5. 依工作類型保留方便使用者後續查看的相關 XQ 視窗，不得只為任務收尾而關閉：
   - 撰寫或編譯腳本：保留本次成果腳本及其 XScript 編輯視窗。
   - 操作 XScript 編輯器，例如建立資料夾或整理腳本：保留 XScript 編輯器及相關分類或位置。
   - 將指標展示在技術線圖：保留已顯示該指標的技術線圖畫面。
6. 操作、除錯或學習期間可在確有需要時建立畫面截圖、局部裁切圖或視覺探測輸出；相關知識已蒸餾並納入知識庫、結果已取得其他可重現證據後，必須刪除非必要的暫存截圖及視覺探測檔，避免專案與本機工作目錄持續膨脹。只有尚未解決的 incident、使用者明確要求保留，或缺少其他替代證據時才能保留最少量影像；保留檔必須置於版本控制排除的私有位置，且不得含帳號、私人策略、部位或其他敏感內容。清理前須精確列出並確認檔案是本次工作所建立，清理後驗證不存在，不得用寬泛路徑或萬用字元誤刪使用者檔案。
7. 切回 ChatGPT／Codex 前，XQ 軟體的主程式視窗必須最大化（非全螢幕）；前款保留的 XScript 編輯器、技術線圖、報告或其他子視窗維持原本大小即可，不得為收尾而強制最大化。「最大化」是保留標題列、視窗框架及 Windows 工作列的標準最大化狀態，不得切換成無邊框或隱藏系統介面的全螢幕模式。若 XQ 主程式尚未最大化，應使用 Windows 正式最大化命令，不得用座標拖曳視窗，並以 `IsZoomed` 或等價的視窗狀態讀回確認。
8. 無論前款保留哪一種 XQ 視窗，任務完成的最後前景一律切回 ChatGPT／Codex；相關 XQ 視窗應維持開啟，不要求仍位於前景。
9. 必須驗證 ChatGPT／Codex 可見且位於前景，並驗證前款要求保留的相關 XQ 視窗仍存在，以及 XQ 主程式視窗保持最大化（非全螢幕）；若環境故障導致無法完成，必須明確回報，不得默認完成。

## 第六條：Print 除錯輸出必須隔離

1. 使用 `Print` 語法除錯時，必須明確指定新的隔離輸出資料夾，避免與 XQ 原生檔案或使用者檔案混雜。
2. 使用者指定的路徑與檔名語法如下；實際使用仍須由當次 XQ 編譯結果驗證：

   ```xs
   print(file("C:\print\"),date,symbol,close);
   print(file("c:\Print\[Symbol].log"),date,symbol,close);
   ```

3. 使用者同時指定「使用者桌面的新資料夾」及上述 `C:\Print\` 範例。兩者在實際環境可能不是同一路徑，因此每次第一次啟用 Print 檔案輸出前，必須向使用者確認最終目標；不得自行猜測、沿用 XQ 預設目錄或覆寫既有檔案。
4. 確認目標後，只能建立新的 CODEX 專用輸出資料夾與新檔案；不得把輸出寫入原生 Print 資料夾。輸出內容不得包含帳號、憑證、私人部位或其他敏感資料。
5. 官方參考：[功能介紹：如何使用 Print 指令進行腳本除錯？](https://www.xq.com.tw/learning/%E5%8A%9F%E8%83%BD%E4%BB%8B%E7%B4%B9%EF%BC%9A%E5%A6%82%E4%BD%95%E4%BD%BF%E7%94%A8print%E6%8C%87%E4%BB%A4%E9%80%B2%E8%A1%8C%E8%85%B3%E6%9C%AC%E9%99%A4%E9%8C%AF%EF%BC%9F/)。該頁的企業版預設路徑不應套用為個人版假設；使用者提供的個人版預設安裝位置為 `C:\SysJust\XQLite`。

## 第七條：回報保持客觀與中立

1. AI 模型只負責回報可觀察的客觀事實，包括軟體設定是否符合指令、腳本是否通過當次真實編譯、執行流程是否正常完成、實際結果與錯誤訊息，以及尚未取得證據的限制。
2. 不得預設、替使用者選擇或暗示任何策略立場、腳本立場、市場方向、商品偏好或交易觀點；使用者沒有指定的策略語意不得自行補入。為完成軟體必要設定而採用的明示預設值，必須標示為可調整設定，不得描述成策略建議。
3. 編譯成功、回測完成、出現訊號或流程正常，都不得延伸推論為策略可行、能獲利、適合實盤、安全或具有投資價值。若使用者要求比較結果，只能陳述實際數據與軟體行為，不替結果下投資結論。

## 第八條：五大類型腳本必須先編譯成功

1. 指標、選股、警示、函數及自動交易五大類型腳本，在進入任何回測或其他使用環境前，都必須先由當次真實 XQ 編譯器回傳 `success`，並證明是同一名稱、同一類型、同一份來源版本。這項前置條件不得由離線檢查、程式碼生成、設定 dry-run、舊回測結果、視窗可開啟、腳本名稱／資料夾讀回或先前工作階段的編譯紀錄代替。
2. 「其他使用環境」至少包含：把指標加入技術線圖、執行選股或選股回測、建立／執行策略雷達或警示回測、由其他腳本呼叫函數、建立／執行自動交易策略，以及自動交易回測。CODEX 禁止的實單與帳號操作不因編譯成功而獲得授權。
3. XScript 視窗標題含「未編譯」、編譯結果缺失／不唯一、來源版本無法對應，或編譯器回傳 `compile_error`／`automation_error` 時，必須立即停止進入任何使用環境。先保留真實編譯訊息，依錯誤修正同一 CODEX 腳本，直到取得當次 `success`；不得嘗試讓 XQ 以舊編譯產物、既有策略引用、直接開啟回測視窗或其他方式繞過編譯。
4. 每個下游工具必須在送出第一個會建立、設定或執行使用環境的輸入前，以機器可讀證據驗證編譯前置條件；只有名稱、類型及 `自訂/CODEX/` 位置符合仍不充分。無法驗證時一律 fail closed，且不得開啟回測、建立策略、加入圖表、執行呼叫端或啟動自動交易。
5. 編譯成功只證明目前 XQ 接受該來源版本，不證明回測能完成、執行結果正確、策略可行、能獲利或適合實盤。後續環境仍須各自取得實際執行證據。

## 操作前後檢查

任何會接觸 XQ 的工作都必須：

1. 操作前讀取本憲法。
2. 確認目標位於已讀回的 CODEX 專區；私人來源只建立副本。
