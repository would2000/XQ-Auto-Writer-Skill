## 核心狀態模型

| 名稱 | 意義 | 產生腳本時的規則 |
| --- | --- | --- |
| `Position` | 策略對單一商品的目標部位 | `0` 是空手，正數是多方，負數是空方。它是策略狀態，不保證等於帳戶庫存。 |
| `Filled` | 策略目前已成交的淨部位 | 用它判斷成交是否完成；`Position = Filled` 才代表成交部位已追上目標。 |
| `Position - Filled` | 目標與成交之間的差距 | 差距不為零通常表示尚有未成交、部分成交、刪改單或回報中的狀態，不可把 `Position` 當成交證明。 |
| `FilledAvgPrice` | 目前未平倉部位的成本 | `Filled = 0` 時為 `0`；有部位時為非負數且不帶多空方向。成本採先進先出，且不含交易成本。 |
| `FilledRecordCount` 與 `FilledRecord*` | 策略執行期間的逐筆成交紀錄 | 部分成交可能產生多筆紀錄。索引從 `1` 到 `FilledRecordCount`，可讀日期、時間、方向、價格、數量與是否為即時成交。 |

一個策略可以同時執行多個商品，但每個商品的 `Position`、`Filled` 與成交紀錄彼此獨立。策略初始部位可以由歷史模擬或帳戶庫存整合設定影響，因此腳本不得假設每次啟動都必然從零開始；若需求依賴初始部位，必須先向使用者確認策略設定。

## `SetPosition` 契約

現行基本形式是：

```text
SetPosition(目標部位)
SetPosition(目標部位, 委託價格)
SetPosition(目標部位, 委託價格, label := "唯一標記")
```

產生程式時遵守以下規則：

1. 第一個參數永遠是「交易後希望到達的總部位」，不是本次買賣數量；加碼一單位可用目前 `Position + 1`，全部平倉則以目標 `0` 表示。
2. 第二個參數才是委託價格。省略時採策略設定的預設買賣價格；`MARKET` 對證券與期貨可能轉成不同的市場委託語意。
3. `AddSpread(價格, 檔數)` 用商品跳動單位調整價格，比直接加減固定金額更能跨商品使用。
4. 目標部位應是整數。現行說明指出小數會被截去，且超過商品單筆最大數量時可能停止該商品執行；程式應在送單前驗證數量。
5. XQ 會依商品小數位、跳動點與漲跌停限制正規化委託價格；這不代表價格一定能成交。
6. `label` 用於辨認成交原因，同一腳本內應保持唯一，且不能拿來替代狀態判斷。

## 洗價、指令優先順序與未成交單

- `Position` 與 `Filled` 會在每次腳本執行開始前形成快照；在同一次執行中呼叫 `SetPosition`，後續程式列不會立刻看到更新後的值。
- 同一次洗價若走到多個交易指令，現行 `SetPosition` 說明指出只採用第一個交易指令，其後指令會被忽略。因此進場、出場、停損與停利條件應設計成互斥分支，並把風險退出的優先序寫清楚。
- 目標部位改變，而先前仍有未完成委託時，系統會先處理舊委託，再依確認後的成交部位與新目標差額重新送單。
- 目標相同但價格改變時，可能形成刪單後改價重送。不要在每次洗價都無條件傳入持續變動的價格，否則策略可能頻繁刪改單。
- 一個商品原則上只保留一筆尚未完成的委託；策略仍須處理部分成交、刪單失敗、交易所拒單與回報延遲。

## 未平倉成本與損益判斷

停損、停利或移動出場若以成交成本為基礎，必須先確認 `Filled <> 0` 且 `FilledAvgPrice > 0`。多單與空單的損益方向相反，不能把同一個價差百分比公式直接套用兩邊。

`FilledAvgPrice` 只代表以先進先出方式計算的未平倉成本，不包含手續費、交易稅、滑價或已實現損益。若需求要計算完整交易績效，應從 `FilledRecord*` 逐筆重建現金流並另外納入成本模型，而不是用未平倉平均價推估全部損益。

## 專章中的委託模式如何落地

下列名稱是由條件與 `SetPosition` 組合出的策略模式，不保證是券商端原生保存的委託：

| 模式 | 蒸餾後的實作觀念 | 必查風險 |
| --- | --- | --- |
| GAT | 驗證目標日期、時間與數量，只有目前日期時間到達門檻後才設定目標部位。 | 日期格式、時區、非交易日、重啟後是否重送。 |
| GTC | 條件持續成立時維持同一目標部位與限價，直到成交或策略停止。 | XQ／券商端是否跨日保留、未成交改價與停止策略後的委託處理。 |
| MIT | 價格碰觸門檻後，將目標部位改成指定數量並使用 `MARKET`。 | 跳空、滑價、觸發資料頻率與市價單支援。 |
| MPM | 以最佳買賣價中點作為限價。 | 中點可能不符合跳動點；報價變動會造成頻繁改價。 |
| 掃價 | 先依各檔報價與數量決定足以容納目標量的價格，再呼叫 `SetPosition(目標部位, 價格)`。 | 專章舊範例的參數順序與現行簽名衝突，不得照抄；也要處理五檔不足與單筆數量上限。 |
| 定時進出 | 時間到達後設定進場或平倉目標。 | 宣告的時間輸入必須真正用在條件中，並確認使用 `Time`、`CurrentTime` 或交易日設定的語意。 |

## 產生自動交易腳本前的必要檢查

1. 明確取得市場、商品、資料頻率、洗價模式與允許交易時段。
2. 明確取得初始部位來源、最大多空部位、單次調整量與是否允許反手。
3. 明確取得委託價格來源、未成交多久後改價或取消、部分成交與拒單的處理方式。
4. 明確取得停損、停利、單日損失、每日次數、收盤前平倉與緊急停止規則。
5. 讓同一次洗價最多走到一個有明確優先序的交易指令；風險退出通常應高於一般訊號。
6. 用 `Filled` 確認成交，用 `Position` 表達目標；不要混用策略部位與帳戶真實庫存。
7. 任何金額、張數、口數、百分比與時間輸入都要驗證範圍與單位。
8. 編譯成功後仍須模擬、回測並在非實盤環境驗證成交、部分成交、拒單、斷線、重啟與收盤邊界；沒有實際測試時一律標示「未驗證」。

## 已知來源差異與不採用內容

- 專章的掃價片段把 `SetPosition` 的前兩個參數寫成近似「價格、數量」的順序，與現行 `SetPosition(目標部位, 委託價格)` 契約衝突，因此不納入可重用範例。
- 專章的開盤定時片段雖宣告時間輸入，條件卻使用固定常數。蒸餾規則要求輸入值必須實際參與判斷。
- 專章用特定台股金額換算張數的算式只能視為示意；不同商品的交易單位、價格、整數化與單筆上限必須重新確認。
- 本次只驗證文件內容與現行語法說明，沒有對 GAT、GTC、MIT、MPM 或掃價模式逐一執行真實 XQ 下單測試；其交易行為均為「未驗證」。
