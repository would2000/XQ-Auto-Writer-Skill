# 警示實際觸發與不觸發驗證指南

本文件記錄 XQ 3.19.03（2026-07-22）在 Windows 桌面實際驗證過的策略雷達操作。它補足警示腳本「編譯成功」與「真的產生／沒有產生訊號」之間的證據缺口。

## 驗證範圍

- 腳本類型：`{@type:sensor}`。
- 觸發方式：條件成立時令 `ret = 1`。
- 公開測試商品：台積電 `2330`，介面讀回為 `台積電(2330)`。
- 執行引擎：策略雷達；警示中心只用於彙總顯示，不用來建立或隔離測試策略。
- 測試模式：`單次洗價模式`。此模式會在啟動後完成一次洗價並自動停止，適合在盤中及休市後做可重現紅燈／綠燈測試。

真實紅燈案例使用一個輸入參數控制 `ret`，參數 `1` 的執行節點顯示 `18:00:20(1)`；綠燈案例把同一參數改為 `0`，執行紀錄依序顯示已啟動及停止，觸發商品頁沒有執行日期或觸發列。這證明的是該商品、該次洗價與該參數的訊號結果，不代表策略獲利、通知送達或任何委託成交。

## 自動驗證工具

先用一般完成流程建立並真實編譯一個帶單一數值參數的警示腳本，例如參數 `1` 時設定 `ret = 1`、參數 `0` 時不設定。之後執行：

```powershell
python .agents/skills/xq-xscript-compiler/scripts/xq_alert.py `
  --script-name CodexAlertRuntimeV1 `
  --product-code 2330 `
  --product-readback '台積電(2330)' `
  --parameter-label '1觸發，0不觸發'
```

工具會：

1. 以無結果哨兵確認唯一策略名稱尚未存在，不覆寫使用者策略。
2. 建立參數 `1`、指定公開商品及單次洗價模式的紅燈策略。
3. 等待單次洗價自動停止，從觸發日期樹解析 `HH:MM:SS(N)`；`N` 必須大於 0。
4. 複製紅燈策略，精確把指定參數改成 `0`，讀回後啟動綠燈案例。
5. 綠燈案例必須正常完成且沒有觸發節點。
6. 預設只刪除本次建立且腳本、商品讀回一致的兩個策略；若工具自行開啟策略雷達，也會在結束時關閉。

單一 JSON 狀態與退出碼：

- `success`／`0`：紅燈有觸發、綠燈完成且為 0 筆，清理亦成功。
- `mismatch`／`2`：流程完成但紅燈或綠燈結果不符。
- `automation_error`／`3`：視窗、讀回、逾時、重名或清理無法證明。

`--keep-strategies` 只供人工除錯；一般驗證不要使用，以免留下測試策略。若清理失敗，即使結果本身相符也降為 `automation_error`，並在 `cleanup.errors` 回報精確名稱。

## 判定與安全邊界

- 「不觸發」不能只用沒有跳出通知判定。至少要同時證明策略完成單次洗價、參數讀回為 0，且該策略的觸發日期樹為空。
- 觸發商品頁是策略範圍證據；不要清除全域警示中心，避免修改使用者紀錄。
- 不用截斷的策略格名稱作刪除依據。刪除前必須以唯一名稱搜尋，再讀回腳本與商品。
- 工具不設定下單模組、帳號或手機傳送，不會送出委託。策略雷達出現觸發也不等同成交。
- `單次洗價模式` 是測試執行模式，不應擅自改變使用者正式警示的觸發模式。
- 策略引用警示腳本時，XScript 編譯器會拒絕重新編譯並提示該警示策略正在使用中；修改腳本前先停止並移除本次測試策略。
- XQ 改版後若 command ID、控制項 ID、頁籤名稱或執行節點格式改變，應重新探測，不可把空白結果當成功。
