操作契約：

- 上述時間只代表正常資料流程的參考排程。交易所公告、上游資訊源、轉檔、通訊或硬體因素都可能延後，而且文章說明不一定另行通知。
- 同一策略引用的價格、信用交易、法人與主力資料可能在不同時間完成。不得因日線已更新，就假設所有盤後欄位已是同一交易日。
- 回測或選股若要求「最新交易日」，執行前應檢查關鍵欄位的資料日期、可用筆數與是否為空值；等待到表列時間仍不是完整性證據。
- 排程應以「資料可用性條件＋合理緩衝」為準，而不是只寫死表列分鐘。文章時間與現行服務不同時，以實際欄位日期、系統公告及目前 XQ 行為為準。
- 跨市場策略須分別處理各交易所交易日、休市與更新節奏，不可用台股時點推定陸港市場資料已完成。

## XQ 警示中心模型

### 入口與三區介面

文章版本的入口為 `策略` → `警示中心`。介面分成：

1. `即時監控（警示紀錄）`：最新觸發置頂，可由商品進入分析；商品右鍵可連動下單列，屬可能影響交易的操作，自動化不得在未授權時使用。
2. `報價組合`：可切換自選報價、類股、全球金融、期貨、選擇權及特別報價；被警示觸發的商品旁會顯示提示及累計數量。
3. `商品盤勢與技術分析`：與警示紀錄及報價組合選取的商品連動。

警示中心是訊號顯示與監控介面，不是委託成交保證。警示出現只證明某次洗價符合條件；資料延遲、頻率、重複觸發與通知設定仍須另外核對。

### 一般警示與通知

- 一般警示由 `設定` → `警示設定` 建立，需指定商品、條件與提示訊息；新增後還要啟用並完成設定。
- 觸發後可出現 `警示提示` 視窗。該視窗可加入自選股、清除紀錄及設定提示來源；這些是介面動作，不等於修改警示腳本。
- 使用者可選擇觸發時不顯示彈窗，之後可由 `設定` → `我的設定` → `警示提示` 重新開啟。沒有彈窗不代表警示沒有執行。
- 即時監控可保留完整警示紀錄並依來源篩選；報價組合上的數字表示該商品累積的觸發項目，可再查看明細。
- 文章另指向策略雷達與雲端監控作進階監控。三者的執行環境、洗價與通知設定不能視為完全相同。

### 撰寫警示腳本時的檢查

- 明確定義商品、頻率、觸發條件、是否只觸發一次及允許重複提醒的節流方式。
- 把「條件成立」、「警示被記錄」、「彈窗顯示」及「使用者看到通知」視為不同狀態，不可合併成一個成功判定。
- 若腳本依賴盤後欄位，先套用資料更新時效契約；資料尚未完成時不得把未觸發解讀成條件不成立。

## `IsFirstCall` 事件語意

`IsFirstCall` 判斷的是「目前洗價是否為指定事件的第一次」，不是程式碼第一次執行到該函數。事件第一次洗價若被外層 `if` 跳過，之後再呼叫也不會補回 `true`。

| 參數 | 何時為 `true` | 適合用途 | 重要陷阱 |
| --- | --- | --- | --- |
| `" "` | 本次腳本執行的第一個洗價事件，僅一次 | 一次性初始化、一次性資料準備 | 若有歷史資料讀取或策略部位計算，會在歷史區間第一根 Bar 成立，不是進入即時行情時成立。 |
| `"Bar"` | 每根新 Bar 的第一次洗價 | Bar 內單次動作、重設 `intrabarpersist` 計數器 | 逐筆洗價時同一 Bar 後續呼叫為 `false`；若要引用完整上一根 Bar 結果，應明確使用前期值。 |
| `"Date"` | 執行商品每個交易日的第一次洗價 | 每日狀態重設、交易日開盤處理 | 依商品交易日切換，不等同午夜或單純 `Date <> Date[1]`。 |
| `"Realtime"` | 每次由歷史洗價區間進入即時區間時的第一次洗價 | 即時啟動時間、只在即時行情初始化的邏輯 | 回測或純歷史區間不應假設會成立；重啟或重新進入即時區間時會再次成立一次。 |

文章版本提供的交易日切換例子為：股票約 09:00、一般期貨約 08:45、全日期貨約 15:00。這些是該版本的商品情境，不是所有市場的固定常數；實作應以執行商品的交易日定義為準。

設計規則：

- Bar 內限制 N 次時，用 `intrabarpersist` 保存計數，並在 `IsFirstCall("Bar")` 時重設；計數只在實際觸發後增加。
- 需要即時區間計時時，在 `IsFirstCall("Realtime")` 初始化起始時間，且後續條件要有「已初始化」防護，避免歷史區間使用預設值。
- 跨日清倉是高影響交易動作；`IsFirstCall("Date")` 只能決定事件時機，仍須檢查 `Position`／`Filled`、未完成委託、商品交易時段及使用者風險要求。
- `IsFirstCall` 不保證委託只送一次；洗價事件、目標部位與實際成交狀態仍須共同設計。

## `Print` 除錯契約

### 支援與輸出位置

- 文章列出指標、選股、警示與交易腳本皆可使用 `Print`，同一次輸出可混合字串與數值。
- 本機執行時可在 XScript 編輯器下方的 `執行` 區查看，並依商品與腳本辨識來源。
- 文章版本的預設檔案目錄為 `C:\SysJust\XQ2005\XS\Print`，預設檔名由腳本及商品組成。安裝路徑可能因版本與安裝方式不同，使用前須以目前環境確認。
- `file(...)` 放在 `Print` 的第一個參數位置，可指定輸出目錄或檔名。文章列出的檔名替代標記為 `[Symbol]`、`[ScriptName]`、`[Freq]`、`[Date]`。

### 回測與選股中心

- 回測與選股中心不會只因腳本含 `Print` 就必然輸出；必須在相應介面另行開啟腳本內 `Print`。
- XQ 3.19.03 的回測設定已實際驗證 `啟動腳本內Print指令`（control ID `2131`）存在。選股中心的開關仍只有文件證據，尚未做真實 UI 探測。
- 文章指出回測與選股中心的 `Print` 由雲端執行，啟用後可能延長執行時間；除錯完成後應關閉高頻輸出。

### 建議輸出內容與安全

- 每列包含足以重建執行上下文的時間、商品、頻率、Bar、事件類型與關鍵條件值。
- 交易腳本另外記錄 `Position`、`Filled`、成本、目標部位、觸發標籤與索引邊界，但不得記錄券商帳號、Token、憑證或其他私人資料。
- 多商品、多腳本或多頻率並行時，優先用替代標記分檔，避免不同來源交錯而無法判讀。
- 不要在每次逐筆洗價無條件輸出大量內容；使用條件閘門、`IsFirstCall` 或短日期／單一商品最小重現降低 I/O 與雲端回測負擔。
- 指定自訂路徑前先確認目錄存在、寫入權限、檔案大小與覆寫／追加行為。不得把 Print 日誌提交到儲存庫。

## 四主題的聯合診斷順序

1. 先確認欄位資料是否已到合理更新時點，並檢查實際資料日期與空值。
2. 再確認腳本洗價事件：目前是歷史、即時、新 Bar 還是新交易日。
3. 用最少量 `Print` 證明條件值及 `IsFirstCall` 狀態，不先改核心交易邏輯。
4. 警示腳本須分別確認條件成立、警示紀錄、來源篩選及彈窗設定。
5. 回測或選股若啟用 Print，將額外耗時納入逾時判讀；完成後再關閉除錯輸出。
