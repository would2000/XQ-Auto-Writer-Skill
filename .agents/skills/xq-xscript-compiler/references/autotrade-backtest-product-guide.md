# 自動交易回測：執行商品選擇與策略動作檢查

狀態：XQ 3.19.03 實機介面觀察（2026-07-26）。本文件只涵蓋歷史回測商品設定；不涵蓋帳號、下單或任何實盤功能。

## 進入與來源

在 XScript 編輯器的自動交易腳本點選「回測」後，會開啟「執行回測[策略]」。

- `執行商品`來源下拉選單為 ComboBox `2092`，預設為「商品」；可讀回的來源還包括「組合」、「選股」、「庫存」與「檔案」。
- 已選商品摘要為 Static `2001`；右側「設定」按鈕為 `2031`。選擇「商品」後通常直接開啟商品選擇器；未自動開啟時可按 `2031`。
- 「組合」與「選股」可能指向使用者私人內容。除非使用者明確指定目標，代理不得瀏覽、選取、儲存或改動其中項目；應停留在選擇器，讓使用者選擇後再讀回最後摘要。

## 商品選擇器

商品選擇器的重要可讀回控制項如下：

- `761`：市場／類別；切換後會更新 `762` 的產業／組合清單。
- `762`：產業／組合；例如選取公開類別「台股指數」後，清單會切換為「上市櫃指數」、「上市19類」、「上市類股」、「上市8大類」與「上櫃類股」。
- `782`：查詢結果；`741` 輸入代碼或名稱，`802` 執行查詢。
- `803`：加入目前選取的結果；`804`：全部加入；`781`：已選清單；`805`：全部刪除；`1`：完成；`806`：取消。

實測中，在公開「台股指數」類別可用「全部加入」將目前結果批次放入已選清單（本次介面讀回 201 列，含一個空白 UI 列）。清空後查詢 `2330`，選取結果並按加入，可讀回「2330 台積電」。按「完成」會回到回測視窗，摘要讀回「台積電(2330)」，且開始回測按鈕可用。這只證明商品設定流程正常，不代表已執行回測。

## 共用逐檔選取實作

自動交易的公開商品選取已集中在 `xq_backtest_scope.py`，並仍由 `xq_backtest.py` 的既有回測流程呼叫。每次執行都會清空暫時清單、確認已清空、精確加入指定商品並讀回最終集合；證據位於 `settings_evidence.product_selection`，同時包含 `selection_mode` 與 `private_source_touched: false`。

此程序只處理回測設定中的暫時商品清單，不會更動使用者自選股或任何私人來源。若清空、唯一比對或最終讀回無法證明，應以自動化錯誤停止，而不是沿用既有選取。

只驗證商品範圍時使用：

```powershell
python .agents/skills/xq-xscript-compiler/scripts/xq_autotrade_backtest.py --config .xq-auto-writer/xq-ui.json --product 2330 --dry-run
```

這個轉接器只開啟目前已驗證的交易腳本回測設定、取代公開逐檔清單、讀回後取消；不填寫頻率、日期、資金、成本、風控、帳號或委託欄位，也不啟動回測或建立 checkpoint。每次實體輸入前都要求精確父視窗 handle 位於 Windows 前景，並在 `settings_evidence.foreground_guard` 與 `scope_selection.foreground_guard` 輸出證據。前景遭其他應用程式遮蔽、切換失敗、視窗 disabled／hung、`WaitGuiThreadIdle`、對話框晚到或 timeout 時，立即停止，不補送取消或重試。

## 回測前策略動作檢查

在按「開始回測」前，必須先檢查目前腳本確有可辨識的策略動作：至少一個進場與一個出場條件，或明確的部位加減碼條件。只含指標計算、Print 或警示訊號的交易腳本不得當作完整交易回測策略。

本次用於介面學習的 `CodexV1FlowAutotrade`，以 `SetPosition(1, MARKET)` 作為進場，並以停利、停損、趨勢轉弱三種 `SetPosition(0, MARKET)` 條件出場，符合此最小檢查。

## 預設與安全界線

本流程只依使用者授權調整「執行商品」，其餘回測控制項維持原值。實際執行回測仍必須遵守 [backtest-configuration-contract.md](backtest-configuration-contract.md)：先取得其中列為必須明確定義的頻率、商品／盤別、日期區間、停利、停損、部位與分鐘 K 收盤處理等設定，再按「開始回測」。回測結果只可客觀描述設定、過程與數據，不可推論策略可行性。

完成學習或設定檢查而未獲得執行授權時，取消回測視窗；不得啟動回測、建立實單連線或操作帳號。

## 正常完成監控

沒有指定取消測試時，`xq_backtest.py` 必須先讀回目前已編譯的交易腳本名稱、類型與 `自訂/CODEX/`，並以腳本名稱作為報告 marker。開始前保存可見報告及全部進度視窗 handle 基準；健康但隱藏的舊進度窗只屬基準，不得誤判成執行中。Start 由共用 `xq_backtest_monitor.py` 只送出一次，之後只讀監控 `starting → running → late_report → completed`。

完成只接受唯一新增、標題 marker 相符且摘要有結論的報告；完成後只關閉該精確 handle。報告不唯一、marker 不符、timeout 或證據不足都保留 checkpoint 並要求人工覆核。`--cancel-after-seconds`、`--cancel-after-completed-products` 或 `--cancel-on-timeout` 是刻意再送 Stop 的獨立測試，不走這條無後續輸入的正常完成路徑。

2026-08-02 的真實 smoke 先在同一任務分別編譯 `CodexV1FlowMomentum` 函數與 `CodexV1FlowAutotrade` 交易腳本，兩者皆為 0 錯誤、0 警告。回測使用公開商品 2330、日頻、2026-06-01 至 2026-06-30、預載要求 1、本金 100 萬、三項安全上限各 1、原始值、買賣觸發價、價差 0、股票成本 0.2%、期貨成本 100 元、模擬逐筆與觸發即成交啟用，其餘每日重置、Print、美股全時段及直接下單停用。因腳本含 `SetTotalBar(20)`，XQ 將預載欄位停用；runner 記錄要求值 1 但 `preload_records_applied: false`，不得聲稱設定已套用。

唯一新增報告的 marker 精確吻合 `CodexV1FlowAutotrade`，XQ 回報成功商品 1、失敗 0、交易 8。報告關閉確認曾晚到，但已讀回報告內容不存在，結果保存 `late_wait_observed: true` 並清除 checkpoint；完成後的 recovery-status 為 `safe_to_start`。這只證明該版本、商品、日期與設定下的歷史回測流程正常，不代表獲利或實盤安全。
