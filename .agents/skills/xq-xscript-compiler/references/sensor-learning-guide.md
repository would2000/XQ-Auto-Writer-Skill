## 策略雷達的狀態模型

策略雷達把警示腳本、執行範圍、頻率、洗價方式、觸發節流與通知／下單選項組成一個執行中的監控策略。操作與證據應拆成下列狀態：

1. 警示腳本已建立並由編譯器接受。
2. 策略雷達已引用正確腳本、參數、頻率與商品範圍。
3. 策略已啟動，而且資料準備與洗價沒有錯誤。
4. 腳本條件在某次洗價令 `ret` 成立。
5. XQ 已記錄觸發商品與時間。
6. 彈窗、手機推播或其他通知已送出。
7. 若另有下單模組，委託已送出、被接受並成交。

前一層成立不能代替後一層證據。特別是「有訊號」不等於「已通知」，「已通知」不等於「已委託」，「已委託」也不等於「已成交」。

文章版本的策略雷達畫面分成功能列、目錄／標籤、策略清單與選定策略的訊息／設定區。執行範圍可來自單一或多個商品、組合、選股結果等來源，但某些來源可能需要額外模組。自訂警示應使用 `{@type:sensor}`，條件成立時設定 `ret`；建立文件、貼入程式與編譯成功只是加入策略雷達前的必要條件。

本專案操作時還要遵守更嚴格的隔離契約：只在已讀回的策略雷達 `CODEX` 分類建立本次項目，不修改使用者原有策略；測試策略必須列入 manifest，結束後依名稱、類型、位置及不存在證據逐一清理。

## 洗價與觸發設定

### 四種觸發節流

| 模式 | 文件蒸餾語意 | 適合的驗證 |
| --- | --- | --- |
| 連續觸發 | 每次條件成立的洗價都可能通知 | 必須計數實際觸發，不可只看第一次 |
| K 棒內單次觸發 | 同一根 Bar 只通知第一次；換 Bar 後可再次通知 | 同 Bar 重複成立與下一 Bar 再成立要分開測 |
| 啟動後只觸發一次 | 此次策略啟動期間只通知第一筆 | 重新啟動是否重置要由目前 XQ 實測 |
| 單次洗價模式 | 對最後一根 Bar 完成一次判斷後停止，行為接近一次性的選股 | 適合紅／綠控制組；仍要證明洗價完成 |

觸發節流是策略設定，不是腳本條件本身。若使用者要求「首次同時符合」，應先明確決定是以腳本序列記住前一狀態，還是使用策略雷達的 K 棒／啟動節流；兩者的重置邊界不同。

### 逐筆、自動與一般洗價

2025-07-18 的「自動洗價」文章描述四種即時運作組合：

| 逐筆洗價 | 自動洗價 | 文件蒸餾語意 |
| --- | --- | --- |
| 關 | 關 | K 棒結束後的首次洗價才計算已結束 Bar |
| 開 | 關 | 商品有成交洗價時執行，文章版本另描述了最短節流 |
| 關 | 開 | 依設定秒數強制運算，不依賴新成交；換 Bar 後會重算已結束 Bar，但該次不觸發警示或交易 |
| 開 | 開 | 有新 Tick 時運算；若一段時間沒有 Tick，再由計時器補一次運算 |

自動洗價只針對啟動完成後的即時區間，不屬於雷達回測，也不會自行生成新 K 棒。商品沒有新成交時，運算仍停留在最後一根實際 K 棒，因此「程式有再次執行」不能解讀為「行情已更新」。

文件列出自動洗價間隔、各市場收單區間、盤前市價單與期貨刪改限制；這些都是 2025-07-18 的版本資訊，不得寫死成現行交易時段。即使自訂洗價區間涵蓋盤前，XQ 仍可能因商品已收盤或不在收單時段而拒絕交易指令。Codex 不得操作實單，且只能在使用者授權及明確識別的內建模擬帳號下測試。

文章同時說明：

- `GetInfo("IsRealTime")` 在計時器洗價時仍表示即時運算。
- `GetInfo("IsTimerMode")` 可辨識此次是否由自動洗價觸發；文章限定警示與交易腳本。
- `q_SimulatedTradePrice`、`q_SimulatedTradeVolume`、`q_SimulatedTradeTime`、`q_SimulatedTradeDate` 提供試搓資訊。
- `q_MarketState` 與 `q_CircuitBreakState` 用來判斷市場／價格穩定措施狀態。

以上函數、欄位、回傳碼及適用腳本在撰寫前都必須重新查目前 XSHelp；本文件沒有保存文章的完整程式範例，也沒有把文件敘述標為編譯器驗證。

## 基準商品與跨商品／跨頻率

基準商品參照是在策略設定中建立一個獨立的參考條件：參考商品、參考頻率與參考腳本符合時，主策略才允許產生通知。它不要求修改主腳本，適合把市場狀態當成外部閘門。

`GetSymbolField` 則是在主腳本運算時直接讀取另一個商品，可再指定來源頻率。兩種方法最重要的差別是洗價時機：

- 基準商品參照跟隨參考商品本身的行情更新，獨立計算參考條件。
- 跨商品／跨頻率寫法跟隨主策略執行商品的洗價，在該次運算中讀取參考商品。

因此即使條件公式相同，只要兩個商品的報價更新時間不同，訊號時點與結果就可能不同。跨頻率取得的是來源期別「當下累積到目前」的值，不應自動視為已完成的週線或月線；索引 `[1]` 的對位也要依來源頻率解讀。撰寫時應查目前 `GetField`／`GetSymbolField`／`GetFieldDate` 文件，並用獨立 expected 驗證日期與值。

## 雷達回測流程與設定契約

文件列出兩個歷史入口：從 XScript 編輯器對警示腳本啟動回測，或從策略雷達項目啟動回測。兩者都進入回測設定。現行自動化不得依賴入口位置或右鍵座標，必須先以正式命令或唯一控制項重新探測。

### 必須記錄的設定

| 區域 | 設定 | 影響 |
| --- | --- | --- |
| 基本 | 交易方向 | 觸發後模擬做多或做空；文章的預設文字有疑似筆誤，不能據此推定 |
| 基本 | 執行頻率 | 決定回測資料頻率，通常由策略設定帶入 |
| 基本 | 開始／結束日期 | 決定歷史區間；區間尾端仍未出場的交易可能被強制結束 |
| 基本 | 執行商品 | 商品、組合、選股、庫存或檔案等來源；支援度與模組需求須現場確認 |
| 進出場 | 腳本參數 | 應讀回每個值，不可只假設沿用策略 |
| 進出場 | 模擬逐筆洗價 | 日頻可能用分鐘資料、週月頻可能用日資料模擬期內發展；未啟用時只在該頻率 Bar 資料上判斷 |
| 進出場 | 最大同時進場次數 | 限制同時未出場交易數；未勾選代表沒有此項上限 |
| 進出場 | 進／出場價格 | 文件列出當期收盤或下期開盤；不同選擇會改變成交時點與績效 |
| 進出場 | 出場方式 | 停利、停損、最大持有期間或文章版本提供的出場腳本；至少一種才可開始 |
| 交易 | 股票／期貨交易費用 | 影響報告損益，不等於真實券商費率已被正確建模 |
| 交易 | 期貨保證金成數 | 影響回測中的投入成本 |
| 其他 | 啟動腳本內 `Print` | 只有明確啟用後才期待回測輸出；可能增加執行時間 |

最大持有期間的「期數」依執行頻率計數；分鐘頻率另可能提供以天數計算。進場 Bar 如何算第一期、出場用哪一根開盤價，應連同 XQ 版本與設定寫進證據，不能只記一個整數。

回測進度百分比、進度窗關閉或任意新報告都不是成功證據。若停止回測並選擇顯示已完成結果，必須把它標為部分結果；不得與完整回測混用。

## 回測報告判讀

文章把報告分成整體統計、商品統計表、商品分析、交易分析及腳本資料。自動化至少應保存：

- 回測設定讀回、腳本參數、成功／失敗商品數及失敗明細。
- 總交易次數；一次完整進場與出場才算一筆。
- 每商品的交易、獲利／虧損次數、勝率、平均與極端單筆報酬。
- 進出場日期、方向、價位、交易序號及逐筆報酬。
- 報告中 XQ 實際顯示的錯誤碼與說明。

文章指出 XQ v6.40 起，整體投資組合的總報酬採時間加權方式，先形成每日投資組合報酬再逐日複利；單商品報告則保留逐筆交易報酬的累積模型。兩者不能直接互相替代。股票報酬可能納入除權息再投資，期貨可能排除換月價差；報告圖上的進出場點仍可能是回測頻率價位，而不是績效計算使用的調整後價格。

連續獲利／虧損只累積報酬同方向延續的區段；區間獲利／虧損則允許中途反向波動，只要尚未突破相應前低／前高。這些指標描述歷史模擬曲線，不證明未來獲利、流動性、滑價、成交能力或實盤安全。

報告可儲存或匯出，且腳本資料頁會顯示腳本內容。這些檔案可能包含私人策略、商品與績效資料；只能放在本機忽略區，沒有使用者明確指定不得提交或公開。

## 手機傳送

文件把手機推播拆成全域手機傳送開關、個別策略的手機欄位、策略執行狀態及 App 端來源篩選。只有全域與個別策略皆啟用、策略正在執行且實際觸發後，才可能在手機端出現策略名稱、方向、商品、價格與時間。

手機圖示或「傳送中」只證明設定狀態，不證明推播已送達；App 端未讀數與來源篩選才是另一層證據。Codex 不得登入手機或 XQ 帳號，因此這部分只作文件知識，不納入自動操作。

## 串接下單與平倉的安全邊界

舊文章描述自訂策略可配置證券／期權的限價、定時及平倉模組，並設定帳號、方向、數量或金額、成交價／觸發價、委託有效方式，以及下單總次數／總金額等安控。設定完成後仍要另外啟用「觸發下單」開關；單純執行警示不必然送單。

平倉模組會依證券／期權、多空與庫存類型選擇反向委託，固定平倉量大於實際庫存時，文章描述會縮到可用庫存；參考價可再依 tick 調整。全域「中止觸發下單」與停止單一策略是高影響動作。

這些知識不授權 Codex 操作交易功能。專案憲法固定：

- 不得登入、登出、串接或選取實際證券帳號，也不得送實單。
- 只有使用者明確授權且介面能正面識別為 XQ 內建模擬帳號時，才可作模擬測試。
- 不得開啟帳號管理來新增帳號，也不得因文章列出模擬帳號名稱就假設目前下拉選項安全。
- 警示執行證據應在不啟用下單模組的情況下取得；安控設定永遠不能被省略。
