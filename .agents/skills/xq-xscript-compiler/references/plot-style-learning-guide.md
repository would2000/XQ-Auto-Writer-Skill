## 已讀回的控制契約

在 XScript 編輯器目前可見的指標公式窗格（本次指標 pane ID `1`）內，左下方「繪圖設定」列有一個 `Button`：

- 標題：`設定`
- Automation ID：`45017`
- 類別：`Button`
- 父階層：目前指標公式窗格 → `繪圖設定` 列

以該控制項的控制層級 `Click`（不帶座標）後，能在目前 XQ 3.19.03 實際開啟 `繪圖設定`（Win32 `#32770`）對話框。這證明入口可抓取且可重用；入口只適用於目前已由使用者手動切到的指標窗格，不能把 pane ID `1` 猜成其他腳本類型的切換命令。

「繪圖設定」是 XScript 編輯器的子視窗，視窗類別為 Win32 `#32770`，標題為 `繪圖設定`，目前未取得可攜的 Automation ID。主要清單是 `SysListView32`，Automation ID `45241`，欄位標題依序為：

1. `序列名稱`
2. `型式`
3. `樣式`
4. `顏色`
5. `座標軸`

清單列以 Plot 序列名稱作為可讀的唯一文字。列本身支援 `SelectionItem` 與 `Invoke`，實測以列的 `Invoke` 可選取該 Plot。各欄可讀回為同列下、按欄位順序排列的 `Text` 子控制項；但 `型式`、`樣式`、`顏色` 與 `座標軸` 仍是 XQ 自繪內容，UIA 文字可能為空，不能把空字串解讀為預設值或特定樣式。

在 Plot 列已由名稱唯一辨識後，以對應欄位的子控制項 `Click`（不帶座標）可開啟自繪選單：

- `型式`選單可在畫面上觀察到 `線條`、`線段`、`柱圖`、`點`。
- `顏色`選單可在畫面上觀察到 `自動`與色票。

上述彈出選單目前只讀回為自繪 `Pane`，選項本身沒有穩定的名稱、Automation ID 或 SelectionItem。依修訂後的 XQ 操作憲法，必須先用 Plot 名稱、欄位、彈窗類別與目前畫面證明已進入正確選單；語意介面探測仍失敗時，才可在該彈窗的當次矩形內使用單步、節流的局部相對座標選取目標，並以選單關閉、儲存格外觀及實際線圖結果交叉驗證。不得沿用固定螢幕座標或只憑色票位置宣稱成功。

視窗內的分頁控制是 `SysTabControl32`、Automation ID `12320`，目前讀回三個分頁：

- `繪圖樣式`
- `座標範圍`
- `查價視窗`

確認與取消按鈕分別為 `Button` Automation ID `1`（`確定`）及 `2`（`取消`）。

## 技術分析圖右鍵設定路徑

2026-07-26 依使用者提供的替代路徑，在 XQ 3.19.03 完成一次無座標探測：

1. 技術圖控制項可由 `AfxWnd140`、control ID `101`，以及直接父層 control ID `110` 唯一辨識。
2. 控制項層級的右鍵沒有開啟選單；將焦點放在該技術圖後送出正式 Context Menu 鍵（Windows `VK_APPS`），可開啟唯一 `XTPPopupBar`。
3. 該選單透過 UIA 暴露具名 `MenuItem`；精確 `設定...` 可用 `Invoke` 開啟 `技術分析設定`。
4. `技術分析設定` 的主分頁是 `SysTabControl32`／Automation ID `12320`，其中 `副圖設定(B)` 可用 `SelectionItem` 選取。
5. 副圖頁左側指標庫是 `SysTreeView32`／Automation ID `1341`，可依 `XS指標 > 自訂 > CODEX > <精確腳本名稱>` 展開及讀回。
6. 中央已加入指標表格是唯一 `MFCGridCtrl`／control ID `9501`。它沒有 UIA 或 MSAA 資料列子項；鍵盤可移動儲存格，但表格本身不能以腳本名稱作語意選取。選到指標儲存格後，只能以右側出現的 Plot 名稱做事後交叉確認。
7. 指標明細分頁是 `SysTabControl32`／Automation ID `6946`；選取有效的副圖指標儲存格後，會讀回 `參數設定`、`繪圖樣式`、`座標範圍`、`查價視窗`，其中 `繪圖樣式`可用 `SelectionItem` 選取。
8. `繪圖樣式`仍使用 `SysListView32`／Automation ID `45241`，Plot 列與欄位結構和 XScript 編輯器內的繪圖設定相同。

這條路徑證明從技術圖到 Plot 清單的大部分流程可無座標完成，但最後點擊型式、樣式或顏色欄後，仍會開啟相同的自繪 `Afx:67E30000:843` 彈窗。彈窗沒有 UIA 子項、MSAA 具名選項、Automation ID、SelectionItem、DefaultAction 或可用鍵盤選取，已符合憲法中「語意介面確實不可用」的必要條件；但仍須針對 `線段`、`柱圖`、`點`或特定樣式／顏色各自完成一次當次彈窗內的局部相對定位與結果驗證，尚未實際驗證的選項不得宣稱已能可靠自動設定。

## 從 XScript 文件頁籤新增主圖疊圖

2026-07-26 在 XQ 3.19.03，以已編譯且位於 `XS指標 > 自訂 > CODEX` 的 `TwentyDayNewHighBuyPoint` 實測第一條主圖疊圖入口：對該 XScript 文件頁籤按右鍵，再選「新增主圖疊圖」。

- XScript 的文件頁籤列為 owner-drawn MDI 區域；UIA 只可讀回對應的 `AfxFrameOrView140` 文件視窗與名稱，沒有可唯一選取的頁籤項目。
- 在已讀回文件名稱、目前視窗及當次畫面後，對頁籤執行一次局部相對右鍵，會開啟 `XTPPopupBar`。此彈出選單未暴露 UIA／MSAA 的具名選單項目，因此需以當次畫面確認目標列，不能重播固定座標。
- 選單中可見且彼此獨立的項目包括「新增主圖疊圖」與「新增副圖指標」；兩者不可混用。選取前者後，XQ 會建立新的未命名技術分析頁面，並在主圖圖例讀回該指標名稱與 Plot 名稱。本次圖例讀回 `TwentyDayNewHighBuyPoint` 與 `20日新高買點`；當期不符合條件時數值顯示 `N/A`，不代表指標未加入。
- 此動作只會展示指標，沒有啟動回測、策略或帳號功能。使用者原有圖表與 XScript 文件不會被覆寫；完成後應保留新技術圖供使用者檢查。

此路徑目前已驗證「由指標腳本頁籤建立主圖疊圖」。若要自動指定商品、頻率、Plot 型式、顏色或驗證歷史每個買點位置，仍須分別取得可讀回設定或獨立圖形／數值證據。

## 指定技術線圖的設定路徑

使用者已開啟指定技術線圖時，應使用「技術線圖 → 內容選單 → 設定… → 技術分析設定」，不使用會另開測試圖的 XScript 頁籤路徑。XQ 3.19.03 的主分頁可讀回「主圖疊圖」與「副圖設定」；前者將 Plot 疊在 K 線主圖，後者管理獨立副圖及既有副圖上的疊圖。兩個頁面都提供左側指標樹與搜尋欄（`1122`），以精確腳本名搜尋後，只能選取 `XS指標 > 自訂 > CODEX` 的唯一命中。

在主圖疊圖頁，`加入疊圖`按鈕為 `1108`，已加入清單為 `9501`；選取後以右側 Plot 名稱讀回確認，再於明細分頁的「繪圖樣式」設定。常見主圖決策是連續價格線（例如通道）或離散訊號（例如突破買點）；後者應用點、箭頭或柱等不跨缺口的樣式，不可用連續線誤導。

副圖樣式應依 Plot 語意分為：單一趨勢線、趨勢線加柱狀圖、以及正負柱狀圖。這是預設選擇框架，不覆蓋使用者明確指定的型式、顏色、線寬、座標軸或圖例需求。型式、樣式與顏色的最後一層仍是 owner-drawn 選單；須先讀回精確 Plot 列，必要時每次只做一個重新定位且可驗證的選取。

## 主圖疊圖的型式與樣式選單實測

2026-07-28 在 XQ 3.19.03，以已加入主圖疊圖的 `(XS)TwentyDayNewHighBuyPoint` 及 Plot `20日新高買點`，由「技術線圖右鍵 → 設定… → 技術分析設定 → 主圖疊圖 → 指標列 → 繪圖樣式」逐項打開選單，取得以下實際畫面證據：

- `型式`固定提供四項：`線條`、`線段`、`柱圖`、`點`。
- `線條`與`線段`共用「樣式選擇」視窗。左欄提供五種沒有文字名稱的圖形線型（實線及四種虛線／點線組合）與`不顯示`；右欄提供由細到粗的七級粗細。因各選項只有圖形，不能自行替它們建立未經 XQ 命名的文字名稱。
- `柱圖`的樣式提供：`單色`、`外框`、`正負`、`漲跌`、`不顯示`。
- `點`會開啟「點樣式選擇」。圖示來源分為`最近`、`系統`、`自訂`，並提供`匯入自訂圖示`；自訂頁在尚未匯入時會顯示空白提示，最近頁只反映本機近期使用紀錄，兩者都不是固定內建清單。
- `點`的系統圖示包含實心／空心的方形、菱形、圓形、上／下三角形、左右三角形、向上／向下箭頭、實心／空心數字及其他符號。清單可捲動；其中已直接看見實心與空心的向上箭頭，因此離散買點可用此樣式，不必把訊號用線條相連。
- `點`的圖示大小提供`小(預設)`、`中`、`大`、`不顯示`。

`TwentyDayNewHighBuyPoint` 只在訊號成立時以 `Plot1(Low, "20日新高買點")` 輸出，其他日期以 `NoPlot(1)` 清除，因此 Plot 的縱向座標由腳本的 `Low` 決定；繪圖樣式只負責把該座標畫成向上箭頭。適合此語意的設定是「型式=`點` → 系統圖示的向上箭頭 → 適當大小 → 使用者指定顏色」。若使用者要求箭頭與 K 棒低點保留額外距離，必須修改 Plot 輸出的價格，不可誤以為圖示樣式會移動座標。

本次只讀取選項並以`取消`離開，沒有套用探索中的型式或樣式。若後續要正式設定，仍須在當次視窗重新確認腳本列、Plot 名稱、型式與圖示，提交後再由主圖上的離散訊號交叉驗證。

同日另完成一次正式套用驗證：在 `(XS)TwentyDayNewHighBuyPoint` 的 `20日新高買點` Plot 將型式設為`點`、系統圖示設為實心向上箭頭、大小保留`小(預設)`、顏色設為純紅色，再以「完成」提交。提交後重新走同一路徑進入設定，精確選取相同指標及 Plot；繪圖樣式列重新讀回`點`、向上箭頭圖示與紅色色票，證明三項設定已持久保存。技術線圖圖例同步由橘色改為紅色；當最後一根資料不符合條件時仍顯示 `N/A`，只代表該 Bar 沒有 Plot 值，不能據此判定設定失敗。

這次也確認 XQ 3.19.03 的「技術分析設定」在遞迴列舉大量子控制項時可能使前端於 `COMCTL32.dll` 發生存取違規；同一學習流程已觀察到兩次。遇到此版本時，禁止重複深度列舉該對話框；應先完成可及性探測，確定選項仍是 owner-drawn 後，改以目前視窗的一次畫面定位、單一步驟、每步截圖讀回與取消／提交後驗證，並記錄 Windows wait incident。

## 安全操作規則

- 進入時先讀回目前可見的指標公式窗格與其唯一 `繪圖設定` 列，再以 Button Automation ID `45017` 開啟；不得用左下角幾何位置猜測或以同名的其他「設定」按鈕替代。
- 先以標題、類別、Automation ID、控制項類型與父子階層唯一辨識視窗及 `45241`，不得使用座標或矩形推算。
- 讀取清單可用 `ListView` 的列文字與欄標題；不得用 Enter 探索列內容。實測 Enter 會觸發對話框的預設 `確定` 動作，可能關閉視窗。
- 可用 Plot 名稱唯一辨識列，再用欄位標題順序唯一辨識同列的儲存格子控制項；不得以畫面幾何位置推算儲存格。
- 自繪彈出選單內尚未取得可唯一辨識的選項控制項；只有在正確 Plot、欄位與彈窗都已讀回後，才可依憲法第四條對本次目標執行一個局部相對座標點擊。每個顏色、線型或粗細都要分別取得前後驗證，不得把一個選項的定位泛化為整張固定座標表。若 XQ 版本提供可讀回的選項控制項，必須改回語意控制並重新校正。
- 技術分析圖路徑應以技術圖 control ID／父層階層加上 Context Menu 鍵開啟選單，再精確 Invoke `設定...`；不得把失敗的控制項右鍵改成圖表內幾何點擊。
- 中央 `MFCGridCtrl` 沒有腳本名稱的可及性讀回；在要提交變更前，必須以右側 Plot 名稱或其他獨立證據證明選到正確指標，不能只依固定列號。
- `欄位`工具列按鈕是「插入欄位」功能，會開啟另一個 `插入欄位` 對話框；它不是「繪圖設定」入口。兩者不得混用。
- 任何探索用子視窗完成後只關閉本次開啟的對話框；使用者原有的 XScript／XQ 視窗及成果視窗必須保留，最後把 ChatGPT／Codex 切回前景。

## MyTrendScoreIndicator 實際觀察與更正

2026-07-25 初次觀察已編譯的 `MyTrendScoreIndicator` 時，只確認了橘／紅兩種線條出現在同一副圖，便誤判為互斥 Plot 已形成分段換色。2026-07-26 重新放大檢視完整副圖後，撤回該結論：

- `趨勢分數`為橘色線條。
- `強勢趨勢分數`為紅色線條。
- 兩者使用同一座標軸 `I`。
- 橘色一般序列仍保留在副圖；紅色強勢序列會跨越沒有強勢數值的區間連線，並未在條件不成立處中斷。
- 畫面目前資料日期為 `07/24`，但紅色序列圖例的最後數值日期為 `04/23`；這是紅線所見延續不等於當期強勢條件成立的直接反證。

XSHelp 的 `NoPlot` 契約只保證清除指定 Plot 在「目前這根 K 棒」的數值，沒有保證線條繪圖器會在前後有效點之間中斷、停止延伸或形成單一序列的動態換色。因此，兩個互斥 Plot 配合 `NoPlot` 且都使用「線條」型式，不能視為可靠的條件式換色方案。

未來判定條件式繪圖成功時，至少要同時驗證：

1. 強勢條件不成立的日期沒有強勢序列資料點。
2. 強勢圖形在不成立區間不會跨點連線或延伸。
3. 一般圖形在強勢區間是否仍可見，符合使用者對「覆蓋標示」或「真正換色」的明確需求。
4. 圖例顯示的日期與目前查價日期一致，不能把歷史最後值誤認為當期值。

「點」或「柱圖」可避免把離散強勢訊號誤看成連續紅線；「線段」是否能形成預期中斷，以及是否能做到真正取代一般線，仍須另做實際編譯與圖形驗證，不能只靠型式名稱推定。

## 對未來指標腳本的適用範圍

XScript 應以 `Plot1`、`Plot2` 等序列及序列名稱建立可辨識的繪圖資料。不同 Plot 序列可在 XQ 的「繪圖設定」中分別設定樣式；目前能可靠讀回列、開啟樣式選單及提交既有設定。自繪選單可依憲法的受控座標例外逐項校正，但在特定顏色、線型、粗細或座標軸值完成實際驗證前，仍不能保證程式化選取結果。尤其不能再把「兩個互斥 Plot＋NoPlot＋線條」直接當成分段換色模板。

若使用者要求未來自動套用特定樣式，需另做一次只針對該樣式的讀回／設定校正。先尋找穩定語意選擇器；只有確認不存在時，才在已識別的當次彈窗內使用局部相對座標，並以實際控制項狀態、畫面或 XQ 結果驗證。若定位或結果無法獨立驗證，必須停在「可人工設定、尚未自動驗證」。

2. 右側 `繪圖樣式`清單精確讀回 `趨勢分數`與`強勢趨勢分數`，並由後者的同列欄位順序唯一開啟`型式`。
3. 自繪型式彈窗再次確認沒有 UIA 子項、MSAA 具名選項、Automation ID、SelectionItem、DefaultAction 或鍵盤選取；因此只在當次彈窗矩形內，以第四列中心的局部相對位置單步選取`點`。該相對位置不是跨工作階段可重播的固定設定，每次仍須重新讀回彈窗矩形與四項順序。
4. 點擊後彈窗關閉，`強勢趨勢分數`的型式儲存格顯示`點`，紅色設定未改變；提交後技術線圖保留完整橘色`趨勢分數`線，強勢日期改為離散紅色方點，原先跨非強勢區間的紅色連線消失。

這次結果驗證了第一種呈現方式：「完整趨勢線＋紅色點標示強勢日期」。它不構成`線段`、`柱圖`、任意色票或真正分段換色的定位證據；這些選項仍須分別校正及驗證。

## MyTrendScoreSegments 實圖驗證失敗

2026-07-26 將已存在於 `XS指標 > 自訂 > CODEX` 的 `MyTrendScoreSegments` 加入另一個副圖，右側 Plot 清單精確讀回`一般趨勢線`與`強勢趨勢線`，樣式分別為橘色與紅色線條。提交後的實際圖形不符合「同一趨勢線真正換色」：

- 原始 `MyTrendScoreIndicator` 的趨勢分數大致位於約 `-200` 至 `200`，但 `MyTrendScoreSegments` 的紅線向下延伸到約 `-2800`，座標尺度明顯失真。
- 紅線跨越長區間形成斜線，接著出現接近垂直的跳回；它沒有沿著橘色趨勢分數逐段接替。
- 圖例中`一般趨勢線`與`強勢趨勢線`仍是兩個獨立序列，不能視為單一序列的動態換色。

該版本以相同 PlotIndex 反覆呼叫 `PlotLine(..., add := 1)`。官方 XSHelp 只確認 `PlotLine(序列編號, x1, y1, x2, y2[, "序列名稱"])`用於繪製直線；本地公開範例說明 `add := 1`會保留先前趨勢線。依實圖推論，將大量逐 Bar 線段累積在兩個 PlotLine 序列，無法保證 XQ 以互斥、連續且不跨缺口的方式組合成條件換色線。此版本因此判定為「已加入並觀察，但呈現失敗」，不得作為真正換色模板。

## MyTrendScoreSegments 修復與實圖驗證成功

2026-07-26 在 XQ 3.19.03 修復同一份 `MyTrendScoreSegments`。腳本於 `CurrentBar = 1` 時，分別對一般與強勢 PlotIndex 畫零長度 `PlotLine` 並指定 `add := 0`，先清除重新計算前保留的線集合；其餘 Bar 才依條件使用 `add := 1` 保留相鄰兩點間的線段。此版本在 `XS指標 > 自訂 > CODEX` 實際編譯成功，訊息為：`MyTrendScoreSegments 編譯成功，0項錯誤，0項警告`。

在技術分析設定的 `副圖設定 > MyTrendScoreSegments > 繪圖樣式` 中，`一般趨勢線`與`強勢趨勢線`的型式選單都只有`線條`與`線段`兩項。兩者皆改為`線段`，顏色維持橘色與紅色。該型式選單是無 UIA／MSAA 子項目的 owner-drawn popup，因此依操作憲法，只在每次重新解析出的目前彈窗矩形內使用一次局部相對點擊，並以儲存格讀回及實際圖形交叉驗證。

實際副圖驗證結果：

- 數值尺度恢復至約 `-200` 至 `200`，與原始趨勢分數一致，不再出現約 `-2800` 的異常延伸。
- 橘色與紅色線段沿同一條 TrendScore 軌跡交替；紅色只出現在強勢條件成立的相鄰區間。
- 非強勢缺口不再被紅線跨越，也沒有先前的長斜線或近垂直跳回。
- 圖例仍會列出兩個 PlotLine 名稱；「視覺上沿同一軌跡換色」不代表 XQ 內部已合併成單一 Plot 序列。

因此，若要保留完整橘線並額外標記強勢日期，仍應採用`完整 Plot＋紅點／柱圖`；若要線條本身真正呈現橘紅分段，則可採用本次已驗證的`重算時清除兩組 PlotLine＋兩組皆設為線段`模式。重新套用至不同商品、週期或 XQ 版本時仍須再次做實圖驗證。

## MyTrendScoreSegments 台股紅綠高對比配色

2026-07-26 在 XQ 3.19.03 的 `副圖設定 > MyTrendScoreSegments > 繪圖樣式` 完成實測。兩組 Plot 維持已驗證的`線段`型式，顏色調整為：

- `一般趨勢線`：純綠 `RGB(0,255,0)`。
- `強勢趨勢線`：純紅 `RGB(255,0,0)`。

此組配色以台股紅漲綠跌為語意基準：一般區間使用綠色，強勢區間使用紅色；在 XQ 黑色副圖背景上具有明顯亮度與色相差異。色票是無 UIA／MSAA 子項目的 owner-drawn popup；先由當次畫面逐格讀取色票 RGB，再在重新解析的目前彈窗矩形內單步選取。第一次一般線誤選到純紅後，儲存格像素驗證立即識別不符，且尚未提交；重新開啟色票後改選純綠，確認儲存格主色為 `RGB(0,255,0)`，強勢儲存格主色為 `RGB(255,0,0)`，才提交設定。

提交後的實際副圖顯示綠色一般線段與紅色強勢線段沿同一 TrendScore 軌跡交替；原本的正常尺度、條件區間中斷及不跨缺口特性均保留。這項證據只適用於目前 XQ 版本、黑色圖表背景及此色票排列；未來仍須重新解析色票矩形與逐格驗證，不得把本次螢幕座標當成固定設定。
