## 選股的三層模型

選股工作不應把腳本、策略與結果混成同一層：

1. **選股腳本**：以 `{@type:filter}` 表示類型，條件成立時設定 `ret`；`Input` 暴露可調參數，`OutputField` 增加結果欄位。
2. **選股策略**：在選股中心指定名稱、方向、商品範圍，並組合欄位條件、排行規則及一個或多個選股腳本。條件可分為全部必須成立與群組中符合指定數量。
3. **執行結果**：某資料日期、商品範圍與策略設定下的命中集合。0 筆可以是成功空集合；它不等於執行錯誤，也不代表策略失效。

腳本編譯成功只證明語法被目前編譯器接受。要宣稱選股成功，還須保存策略名稱、範圍、資料日期、參數讀回、命中數、錯誤商品數與 XQ 實際輸出證據。

## 選股中心、每日清單與策略組合

官方早期文章把選股中心畫面拆成工具列、目錄、策略清單、條件內容、結果及 K 線預覽。一般流程是選取策略、執行、檢視結果，再按需要加入自選或匯出。這些區塊的現行入口與控制項不得從圖片位置推測，必須依 `screener-window-guide.md` 的目前實測證據操作。

建立策略時應明確記錄：

- 名稱、方向、商品範圍及備註。
- 每個欄位條件的頻率、參數及比較方式。
- 排行的母體範圍、方向，以及取固定名次或百分位。
- 加入的選股腳本與輸入值。
- 哪些條件必須全部成立，哪些屬於「多條中至少符合若干條」的群組。

「每日自動執行」會在資料更新後重跑策略並形成每日選股清單；舊文另描述全部、多方、空方統計及符合策略明細。這類清單可作為策略雷達的商品來源，但不代表盤中一定有新報價，也不代表雷達已啟動或觸發。文章所述策略數上限、警示中心入口及更新時點都要在目前版本重新讀回。

Codex 不得讀取、修改或沿用使用者私人自選與私人策略。自動測試只能建立在已驗證的 `CODEX` 專區與公開系統商品範圍，並依 manifest 清理本次建立項目。

## 自訂腳本、結果欄位與排行

當內建欄位條件不足時，可建立選股腳本、完成真實編譯，再加入選股策略。常見設計契約：

- `ret` 只表達是否入選，不應同時被誤解為分數。
- `OutputField` 將診斷值、因子值或日期帶到結果表；其欄位索引應唯一且穩定。
- `OutputField` 與 `GetFieldDate` 的舊版診斷案例及資料日期邊界另見 [xspractice-learning-guide.md](xspractice-learning-guide.md)；不得把資料期別日期當成公告時間或程式執行日。
- 官方文章記錄 `OutputField` 的 `order := 1` 為由大到小、`order := -1` 為由小到大。這是文件蒸餾，使用前仍應查目前 XSHelp 並實際編譯。
- 自訂排行使用數值函數的回傳值作排序依據；必須設定函數輸入、足夠資料讀取、執行頻率、排序方向，以及取前幾名或前幾百分比。
- 排行結果依賴當次母體。市場、範圍或可用資料改變時，即使函數值不變，名次與百分位仍可能改變。

使用前期值、EMA、MACD 或其他暖機運算時，資料讀取範圍要覆蓋索引、計算期數及穩定期。不能只因編譯成功就假設排行值正確。

## 因子分析

因子是描述商品特徵的數值，可來自基本面、技術面、籌碼面或價量資料。因子分析以數值函數作入口，在歷史樣本中把因子值分組，再比較後續報酬，用來檢查因子是否具有排序或區分能力。

標準流程是：

1. 建立並編譯一個回傳數值的函數。
2. 設定日期、樣本範圍、報酬觀察方式及離群值處理。
3. 執行每日計算與分組。
4. 檢查分組報酬、勝率、分布、樣本數及跨年度穩定性。
5. 若證據足夠，再把因子作為選股排行或條件之一。

文章列出三種樣本處理：保留原值、以 ZScore 排除絕對值大於 3 的樣本，以及以 IQR 排除低於 `Q1 - 1.5 × IQR` 或高於 `Q3 + 1.5 × IQR` 的樣本。選擇方法前應先看因子分布，且必須把處理方式寫入結果證據，避免不同設定的報告被誤比。

因子報表的重點不是單一最高報酬，而是：

- 分組結果是否大致單調，極端組是否有可解釋差異。
- 因子與報酬分布是否被少數離群值主導。
- 每日有效樣本數是否足以代表目標市場。
- 不同年度是否維持方向與效果。
- 報酬、風險報酬比、樣本勝率及年度勝率是否一致支持假設。

歷史因子表現可能受樣本選擇、前視偏誤、存活者偏誤、資料修訂、交易成本及過度擬合影響。因子分析、選股回測或文章標題中的「高勝率」都不保證未來獲利。

## 回溯與回測

### 回溯

回溯是在指定過去日期重新檢視選股結果，可前後切換日期、用日曆選日或回到最新資料。舊文指出結果表中的即時成交、漲幅與總量可能仍顯示最新轉檔值，另以回溯日收盤價及區間漲幅呈現歷史比較。因此擷取回溯結果時，必須分清：

- 策略的篩選日期。
- 欄位值的資料日期。
- 最新行情欄位與回溯日欄位。
- 區間漲幅的起訖與計算基準。

不能因表格出現在回溯頁就假設每一欄都是回溯日資料。

### 回測

文件列出兩個入口：從選股中心的策略，或從 XScript 編輯器中的選股腳本開始。自動化不得使用右鍵座標；入口、報告 handle 與 marker 必須依目前環境安全讀回。

回測證據至少包含：

| 區域 | 必須保存的設定或結果 |
| --- | --- |
| 基本 | 頻率、日期區間、市場、商品範圍、交易方向 |
| 策略 | 欄位／腳本參數、資料讀取與進場設定 |
| 出場 | 出場條件、停利停損、持有期間或出場腳本 |
| 成本 | 交易費用及其他會改變報酬的假設 |
| 執行 | 開始時間、進度、是否人工停止、成功／失敗商品數 |
| 報告 | 交易數、績效欄位、失敗明細、實際錯誤碼、marker 與執行證據 |

停止後選擇顯示已完成商品，只能標為部分結果。進度 100%、任意新報告或視窗關閉都不是單獨成功證據；專案 runner 仍須用唯一新增報告 handle 與指定 marker 完成安全配對。

策略雷達回測也可把選股策略當成商品來源或進場條件。此時要同時保存選股日期語意、雷達腳本設定與商品集合形成方式，不能把「今天已存在的清單」錯當成每個歷史日期都使用相同成分。

## 題材型策略的可重用設計模式

指定範圍中的應用文章只作設計模式，不保存完整程式或股票名單：

- **股權分散**：以週頻股權分散資料觀察大戶或散戶比例的變化。文章列出 100、200、400、600、800、1000 張門檻；同一數字在大戶欄位表示門檻以上，在散戶欄位表示門檻以下。欄位、參數與支援腳本仍須查目前 XSHelp。
- **除息事件**：先取得事件日期，確認距今天數，再把事件日對位到 K 棒，計算事件日至今的漲跌。資料筆數至少要覆蓋最大事件窗口；事件日期、交易日與 K 棒 offset 不能混用。
- **存股篩選**：可把長期股利、最近獲利、長期衰退、董監持股及近期營收趨勢分層過濾。文章中的門檻、舊股票名單及歷史績效只是示例，不是現行建議或獲利保證；財報單位、公布時點及修訂也要核對。
- **籌碼集中度**：可用一段期間的主力買賣超累計相對於同期成交量，形成百分比型函數，再搭配同期價格漲幅上限。分母為零、期數小於 1、`days - 1` 索引及資料長度都應明確防護。

這些模式若要轉成新腳本，仍須依 Skill 搜尋同類型本地範例與目前 XSHelp，保持使用者公式，再走真實編譯閉環。
