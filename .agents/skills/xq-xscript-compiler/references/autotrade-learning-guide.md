## 整體工作模型

自動交易流程分成三層，三者不可混為一談：

1. **交易腳本**：在 XScript 編輯器描述訊號、目標部位、委託價格與風險規則。
2. **回測系統**：用歷史資料模擬洗價、委託與成交，檢查邏輯及績效；不會送到券商。
3. **自動交易中心**：綁定腳本、商品、頻率、部位來源與交易帳號，負責即時運算、送單、監控、排程及紀錄。

因此，腳本編譯成功不代表回測設定正確；回測結果也不代表即時帳號、庫存同步、委託條件或排程已設定完成。

## 建立策略前必須取得的設定

### 執行商品

介面可從五種來源建立商品清單：指定商品、指定組合、指定選股法、指定庫存與指定檔案。若使用選股法，啟動時會先篩選，再把符合者交給交易腳本。使用者需求若涉及跨日持倉，還要決定前期持倉但本期未入選的商品是否繼續執行。

### 頻率與洗價模式

- 未啟用逐筆或自動洗價：主要在 K 棒結束後運算已完成的 Bar。
- 逐筆洗價：行情有新 Tick 時運算；文章記載相鄰運算最短約 0.125 秒，但此數值應視為版本相關設定。
- 自動洗價：即使沒有新 Tick，也依設定時段與間隔使用最近資料運算；介面文章記載間隔可設 1 至 60 秒。
- 同時啟用：新 Tick 立即運算，無 Tick 時由自動洗價補充運算。

腳本設計必須知道是哪一種模式。Bar 內狀態、重複送單、時間條件及 `IsFirstCall` 的結果都會受洗價模式影響。

### 帳號與下單設定

- 一個策略一次只對應一個交易帳號；同一邏輯若要分別使用多家券商，需建立多個策略實例。
- 未設定帳號仍可用即時行情模擬成交，不代表已允許送出實單。
- 帳號商品類型必須與執行商品相容；不相容商品可能在啟動時被略過。
- 證券帳號還須明確選擇現股或信用交易語意，因為庫存與買賣方向會影響實際委託類別。
- 介面可選 ROD 或 IOC。IOC 未成交遭取消後，系統可能把 `Position` 修正回可達成的狀態；文章版本不支援 FOK。
- 交易成本設定影響介面損益顯示，但不等同腳本中的 `FilledAvgPrice` 已包含成本。
- 交易回報等待時間逾時時，系統會中止該商品的自動交易；這是安全機制，不應以重複下單規避。

## 策略部位與實際庫存

啟動策略前須選擇部位來源，四種模式的語意不同：

| 模式 | 啟動語意 | 適用情境與風險 |
| --- | --- | --- |
| 不設定 | 策略部位從 0 開始 | 適合單純測試；不得假設帳戶真的空手。 |
| 延續前次執行 | 載入本機保存的最近未平倉策略紀錄 | 適合跨日策略；紀錄缺失或換電腦時需人工核對部位、成本與建立日期。 |
| 與庫存同步 | 以帳戶庫存建立／更新策略部位 | 可接手手動單或其他策略造成的庫存；同步可能在委託完成後才發生，且可能觸發商品重新運算。 |
| 由腳本計算 | 從指定起點先跑歷史資料，推導策略狀態 | 是模擬計算，可能與真實庫存不同；適合重建變數及策略狀態，不可當帳戶庫存證明。 |

「與庫存同步」另有三個獨立選項：啟動時納入已有庫存、盤中新增庫存時加入執行、庫存異動時同步數值。啟用後，手動交易或其他策略也可能改變本策略看到的部位。腳本若只允許原始清單商品，可用 `IsListedSymbol` 區分原設定商品與後來加入者。

## 交易腳本契約

### `Position`、`Filled` 與 `SetPosition`

- `Position` 是策略希望到達的目標部位；交易指令發出後可能先改變。
- `Filled` 是已成交淨部位；只有成交回報後才改變。
- `SetPosition` 的數量代表交易後目標總部位，不是單次買賣量。
- 未成交或部分成交期間可能出現 `Position <> Filled`，程式不能把目標部位當成交證明。
- `MARKET` 表示使用市場價格語意；`AddSpread` 依商品跳動單位調整委託價，比固定加減金額更適合跨商品。

### `FilledAvgPrice`

`FilledAvgPrice` 是目前未平倉部位成本，空手時為 0。計算停損停利百分比前先確認 `Filled <> 0` 且成本大於 0，避免除以零。它不包含交易成本，也不能代表帳戶全部歷史交易的完整損益。

### 帳號環境資訊

`GetInfo` 可取得策略執行環境：

| 鍵值 | 蒸餾語意 |
| --- | --- |
| `AT_EnableTrade` | 即時且已設定模擬或券商帳號時為 1；回測或未設帳號時為 0。 |
| `AT_BID` | 券商代碼；未啟用帳號或回測時為空字串。 |
| `AT_AccType` | 業務類別：證券 1、期貨 2、複委託 3；沒有帳號時為 0。 |
| `AT_AID` | 券商代碼與帳號組成的識別字串；沒有帳號或回測時為空字串。 |

帳號識別碼屬敏感資料，不得寫入知識庫、日誌或交付範例。若真的需要限制帳號，應使用輸入參數或安全設定，並注意文章指出帳號字串有大小寫，而 XS 一般字串比較預設可能忽略大小寫。

### `IsFirstCall`

| 事件 | 成立時機 | 常見用途 |
| --- | --- | --- |
| 空字串 | 本次執行的第一個洗價事件 | 一次性初始化；若有歷史運算，可能在歷史區第一筆就已成立。 |
| `Bar` | 每根 Bar 的第一次洗價 | Bar 內計數歸零或單次判斷。 |
| `Date` | 每個商品交易日的第一次洗價 | 跨交易日重置或開盤處理；不是單純午夜換日。 |
| `Realtime` | 從歷史資料區進入即時洗價區的第一次洗價 | 記錄即時啟動時間或只在即時區初始化。 |

這些值描述當次事件狀態，不是「函數第一次被程式流程執行」。若第一次事件被外層條件跳過，之後再呼叫也不會補回 `true`。股票、一般期貨與全日期貨的交易日切換時間不同，跨日邏輯應使用商品交易日語意。

## 回測設定與解讀

### 成交時間模型

- 預先執行筆數只用來在正式回測區間前暖機計算，功能近似資料讀取筆數。
- 腳本有指定價格時，模擬委託依該價格處理；未指定時使用策略介面的預設買賣價格。
- 一般情況下，觸發後的委託會在下一個回測洗價判斷是否成交。
- 啟用「觸發即判斷成交」會允許用同一次觸發資料立即撮合，可能明顯改變成交價與績效，必須記錄在測試設定中。
- 「每日部位歸零」是回測介面提供的當沖清倉假設，不等同實盤腳本已具備收盤前平倉與失敗處理。

### 績效解讀

- 初始資金供百分比型績效指標計算，但回測不一定用它阻止資金不足的委託。
- 最大投入報酬率以淨利相對最大投入金額衡量；另可切換時間加權報酬率與淨利曲線。
- 報告可比較買進持有與大盤指數報酬，並分別檢視全部、多方及空方績效。
- 勝率不能單獨判定穩健度；至少同時查看獲利因子、平均賺賠比、最大區間虧損、投入金額及交易樣本數。
- 回測是歷史模擬，沒有證明即時流動性、滑價、斷線、拒單、券商回報與庫存同步行為。

## 介面管理、監控與排程

- 入口位於「策略 → 自動交易中心」。目錄區管理策略分類，工作區以分頁呈現腳本設定、安控、商品監控與執行紀錄。
- 策略匯入／匯出使用 `.xso`。匯出時若依賴選股策略或自訂函數，必須一併包含，否則移轉後可能無法運作；可另外設定隱藏程式碼與匯入密碼。
- 商品監控要同時看目標部位、實際部位、損益、狀態、剩餘委託與成交量，不能只看策略是否顯示「執行中」。
- 執行紀錄區分訊息、警示、交易、委託、成交與錯誤等事件；文章版本提供近 10 日紀錄並可匯出。
- 成交與腳本 `Alert` 可送到即時監控、警示提示及手機推播；需要先啟用 `XS-自動交易` 來源與手機推播。
- 排程設定的是未來符合時間時啟動／停止；新增排程不代表策略立刻啟動。若程式或電腦中斷，重新開啟 XQ 且仍在排程區間內時可能重新啟動，仍須人工核對帳號、庫存與未完成委託。
- 執行總覽可依帳號、策略名稱、部位、排程、損益與多空方向篩選，並彙總損益、實際多空部位、淨部位及執行中策略數。停止全部策略是高影響操作，未來 UI Skill 必須要求明確使用者授權。
- 文章版本指出不支援零股自動交易；此類商品支援限制在真正操作前須重新核對現行版本。

## 除錯與問題回報

逐碼差異、第一輪檢查與客服回報安全契約見 [autotrade-error-codes.md](autotrade-error-codes.md)。以下只保留族群層級摘要。

### 先分類，再修正

| 代碼族群 | 問題類型 | 優先檢查 |
| --- | --- | --- |
| 1000–1004 | 腳本版本、物件、參數、DLL 或欄位轉換 | 重新編譯、腳本版本、參數型態與安裝完整性。 |
| 1100–1102 | 頻率、成交紀錄索引或語法不支援 | 腳本類型、執行頻率與索引邊界。 |
| 1200–1204 | 商品、歷史資料或選股階段 | 商品代碼、資料支援與選股來源。 |
| 1300–1307 | 逾時、主動停止、執行／系統／網路錯誤 | `RaiseRunTimeError`、執行紀錄、連線與停止原因。 |
| 1400–1405 | 資料形態、資料不足、權限、欄位或空值 | 欄位支援、訂閱權限、回看筆數與空值防護。 |
| 1500–1501 | 交易模組或外部委託異動 | 券商回報、手動單、其他策略與庫存同步。 |

策略執行與回測對部分相同代碼的文字定義不同：`1300` 在策略執行表指向逾時，在回測表則表示運算終止；`1307` 只出現在策略執行表。診斷時必須先記錄錯誤發生在哪個流程。無法排除時，官方文章要求準備問題描述、完整畫面、含依賴的策略匯出檔、交易腳本及 XQ Log；分享前必須先移除帳號、憑證與私人策略資料。

### 使用 `Print` 觀察狀態

`IsFirstCall` 的四種事件、資料時效、警示紀錄與 `Print` 檔案／介面契約的完整蒸餾見 [runtime-data-alert-debugging.md](runtime-data-alert-debugging.md)。

- `Print` 可混合輸出字串與數值，適用於指標、選股、警示及交易腳本。
- 執行結果可在 XScript 編輯器的「執行」區查看；本機也會產生日誌。
- `file(...)` 可指定輸出路徑或檔名，並可用商品、腳本、頻率與日期等替代標記分類輸出。
- 回測或選股中心需要在介面另行啟用腳本內 `Print`；雲端執行可能使回測變慢。
- 除錯輸出應包含日期時間、商品、頻率、Bar、條件值、`Position`、`Filled`、成本及委託原因，但不得輸出券商帳號、Token 或其他私人資料。
- 完成除錯後應關閉或限縮大量輸出，避免 I/O 影響執行與累積敏感日誌。

## 後續建立 XQ 視窗 Skill 時的邊界

這份文件只定義「應操作什麼」與「操作後應驗證什麼」，沒有保存螢幕座標或假設控制項識別碼。已完成驗證的 XScript 入口與自動交易中心控制項記錄在 [autotrade-window-guide.md](autotrade-window-guide.md)；其餘視窗仍應在真實 XQ 中逐項探測：

1. 策略新增、匯入、匯出、編輯與啟動入口。
2. 商品、頻率、逐筆／自動洗價、資料筆數與帳號設定控制項。
3. 部位來源、庫存同步、安控、交易成本與回報等待設定。
4. 回測入口、設定欄位、執行進度、完成報告、重新回測與缺少商品檔案的返回流程已完成真實視窗探測；執行期錯誤、停止、逾時及實際匯出仍待專門驗證。
5. 商品監控、執行紀錄、排程、執行總覽、通知與停止操作。

任何會啟動策略、綁定帳號、送出實單、同步庫存、停止全部策略或覆寫設定的操作，都必須先確認目標策略、帳號環境及使用者授權；UI 成功點擊也不代表交易結果正確。
